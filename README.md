## معماری Agent
برای هر مسئله، مراحل زیر انجام می‌شود (فقط با مدل Local در Ollama):
1. **Analyst (تحلیلگر فرمت):** فرمت پاسخ (عدد صحیح، حرف، یکی از گزینه‌های مجاز، الگوی دقیق مثل `Name=<integer>`) از خود متن مسئله استخراج می‌شود. موارد استخراج‌شده فقط در صورتی پذیرفته می‌شوند که واقعاً در متن مسئله وجود داشته باشند.
2. **Program-Aided Solver:** مدل ابتدا قیود را به‌صورت کامنت فهرست می‌کند و سپس برنامه Python (جستجوی کامل، شبیه‌سازی، BFS و ...) می‌نویسد؛ برنامه در یک فرایند ایزوله با محدودیت زمان اجرا می‌شود. در صورت خطا یک دور **Reflection/Repair** انجام می‌شود.
3. **CoT Solver:** استدلال گام‌به‌گام (حالت thinking مدل) همراه با بررسی همه قیود.
4. **Self-Consistency:** پاسخ‌های مستقل رأی‌گیری می‌شوند و به‌محض توافق دو پاسخ، اجرا متوقف می‌شود (کاهش تعداد فراخوانی و زمان).
5. **Judge/Verifier:** در صورت اختلاف پاسخ‌ها، یک مرحله بررسی‌کننده هر گزینه را با قیود مسئله چک می‌کند.
6. **Normalizer/Validator:** پاسخ نهایی تمیز می‌شود (حذف Markdown، «پاسخ:»، توضیح اضافه، تبدیل ارقام فارسی) و با فرمت خواسته‌شده اعتبارسنجی می‌شود؛ فیلد `answer` فقط پاسخ نهایی است.

مدیریت خطا: Timeout هر فراخوانی، بودجه زمان و تعداد فراخوانی برای هر مسئله، و در هر شرایط (حتی خطا) نوشتن JSON معتبر در خروجی.
هیچ پاسخی Hard-code نشده و هیچ مسئله‌ای شناسایی مستقیم نمی‌شود.

## پشتیبانی از ۱۰ نوع مسئله 
- **Task Router** (`reasoning_agent/task_types.py`): نوع استدلال با امتیازدهی کلیدواژه‌ای (بدون فراخوانی LLM) تشخیص داده می‌شود: algebra، ordering، logic، temporal، sets، quant، assignment، knights (راستگو/دروغگو)، grid (BFS)، code (ترکیب چند قید). برای هر نوع یک **روش حل** (نه پاسخ) به Solverها داده می‌شود.
- **ترجمه + واژه‌نامه:** Analyst در همان یک فراخوانی ترجمه انگلیسی دقیق مسئله را هم برمی‌گرداند (متن اصلی مرجع می‌ماند). نام روزهای فارسی و بازه‌هایی مثل «دوشنبه تا پنج‌شنبه» به‌صورت قطعی به لیست روزها تبدیل می‌شوند.
- **تشخیص قطعی فرمت** (`detect_format`): قالب‌های تودرتو مثل `<Nima=<integer>, ...>`، لیست گزینه‌ها (`/`، `|`، خط جدید، کاما)، «فقط عدد صحیح»، «فقط حرف»، «کد سه‌رقمی». این قوانین بر حدس LLM اولویت دارند.
- **شمارش کامل جواب‌ها:** برنامه تولیدشده خط `SOLUTIONS: [...]` هم چاپ می‌کند. صفر جواب = مدل‌سازی غلط ← Repair. چند جواب = ابهام ← اگر دو برنامه مستقل همان مجموعه را بیابند، **Disambiguator** یکی را با بازخوانی متن انتخاب می‌کند.
- **نرمال‌سازی بیشتر:** `(4, 1, 3)` ← `413`، `599.9999` ← `600`، `['C']` ← `C`، بازگرداندن `<` و `>` جاافتاده در قالب، نگاشت «سه‌شنبه» به `Tuesday`.
- `main.py`: اعتبارسنجی هر رکورد، نوشتن اتمی و تدریجی خروجی (حتی با قطع اجرا JSON معتبر می‌ماند).
- تست آفلاین (بدون Ollama): `python -m unittest discover -s tests -v`

## تنظیمات (متغیرهای محیطی، اختیاری)
| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `OLLAMA_MODEL` | `qwen3:8b` | نام مدل |
| `AGENT_MAX_CALLS` | 10 | حداکثر فراخوانی LLM برای هر مسئله |
| `AGENT_TIME_BUDGET` | 240 | حداکثر ثانیه برای هر مسئله |
| `AGENT_CALL_TIMEOUT` | 150 | Timeout هر فراخوانی (ثانیه) |
| `AGENT_CODE_TIMEOUT` | 10 | Timeout اجرای برنامه تولیدشده |
| `AGENT_TRANSLATE` | 1 | ترجمه انگلیسی کمکی برای مسائل فارسی |
| `AGENT_DISAMBIG_CALLS` | 2 | حداکثر فراخوانی برای انتخاب بین جواب‌های مبهم |
